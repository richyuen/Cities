All four are different buildings, different zones, different levels, and different footprint sizes than the builder's own `r3-custom/camera-collision-proof-*.png` test — this is a genuinely independent confirmation that the fix works through the shipped `setCamera`/`update()` path, not just for the one instance the builder screenshotted. Zero errors in any of these captures.

**One real finding from this testing: the collision box is looser than its own code comment implies.** `clampOutsideBuildings` builds its AABB from `world.cellToWorld(b.i,b.j)` ± `cellSize/2` ± `margin(0.6m)` — i.e. the *raw grid cell footprint*, not the generator's actual rendered wall (which is inset `marginBase=0.75m` per side inside the cell, per `generator.js` line 401). Net effect: the camera can never get closer than `(cellSize/2 - (cellSize/2 - marginBase)) + margin = marginBase + margin = 1.35m` from the real wall surface while inside a footprint, not the `0.6m` the variable name suggests. I confirmed this directly: a `setCamera` request placed 0.84m outside the *visual* office-tower wall (well clear of it) was still silently relocated by `clampOutsideBuildings`, because it was inside the looser cell-grid box (`shots/buildings/r3c-custom/pilaster-spandrel-cornerA-r3c.png` / `cornerB-r3c.png` — both show the camera landed much further back than requested, corner not even in frame). This is not a visual bug — every clamped screenshot I took still looks correct, no popping/clipping/awkward angles, and 1.35m is still close enough to read facade detail clearly — but it does mean true sub-1.35m "extreme closeup" inspection shots (the kind round 1/2/3 all used to hunt for the pilaster seam) are no longer reachable through the ordinary `setCamera` path at all, for any building, regardless of requested position, as long as it's within the enlarged cell box. Worth tightening `clampOutsideBuildings`'s AABB to match the generator's actual visual footprint (or exposing `marginBase` for it to use) in a future round, but it's a minor precision nit, not a regression — and see below for how I still verified the pilaster fix around it (narrow-FOV technique from outside the clamp box).

## Ranked issues (most damaging first)
